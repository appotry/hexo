什么时候看这篇？

你是谁你该看什么你能得到什么

1.4 边界与坑

  • 执行顺序不是文档顺序：manifest 行序 = 执行序，L10 最先跑（在 L1 之前）。旧文档常把 L1 写在第一行——那是文档习惯，不是执行事实。
  • 层脚本本身不能直接执行：layers/*.sh 只定义 run_LXX()，依赖 release-test.sh 先 source lib/assert.sh（pass/fail 是全局计数器）。要单独验证一层，跑它内部对应的测试文件，而不是 bash layers/L13_units.sh。
  • 层脚本缺失即硬失败：manifest 里写了某文件但 layers/ 下没有 → ❌ 层脚本缺失：xxx.sh 直接 exit 1，不会静默跳过。
  • L13 与 L13a 有重叠：L13 是"点名跑"（失败时名字清晰），L13a 是"通配扫 unit/** 并卡覆盖率"，同一文件可能被跑两次，这是刻意的双保险。

1.5 小结

层清单只在一个文件里：tools/tests/layers/manifest。想知道"有哪几层、按什么顺序跑"，永远看它，不看文档也不看聊天记录。

3.4 边界与坑

  • L11 本地必跳：--local 会整段跳过（⏭️ 跳过 L11 playwright 集成（--local：…）），所以"本地全绿"不等于"浏览器层没坏"。
  • L11 的通过判据不统一：有的文件看 PASS=N FAIL=0，有的看 0 失败，lazyload 干脆没有汇总行（判据是"没有 FAIL/失败/❌"）。新增文件时必须对齐既有判据，否则会假绿。
  • L14 失败自动重试一次：⚠️ L14 xxx 第 1 次未通过（疑似负载抖动），重试一次…，重试通过会记入 flaky 列表（见 §11），不改变 PASS/FAIL 计数。
  • 未挂层文件已清零：wiki-integration.test.js、infinite-scroll-integration.test.js 早期存在但没进任何层，现已分别于 2026-09-27 / L11 段接入，有断言兜底。唯一仍未挂层的是 tools/tests/unit-fontawesome.test.py（L13a 的通配只收 .test.js），需手动跑 python3 tools/tests/unit-fontawesome.test.py。

3.5 小结

层数不等于覆盖度：L1/L13 是"能不能跑起来"，L2/L7/L8 是"产物里有没有"，L11/L14 是"浏览器里对不对"。三层缺一层，故障就会从缺的那层漏出去。

5.4 边界与坑

  • 重试次数/退避是固定的：3 次、1s/4s/9s + 抖动。不要为了"让它绿"而调大——unit-retry.test.sh 会校验退避库行为。
  • 不要给纯静态断言套 retry_match：本地文件读不到不是网络抖动，重试只会把真 bug 拖成 3 倍耗时。
  • retry_match 的模式必须锚定失败数为 0：只匹配 PASS= 会把"4/24 通过"判成绿（2026-10-07 已因此收紧判据）。
  • 日志落在 /tmp/opencode/：报红先看 📄 日志: 那一行给出的文件，比翻终端滚动区快。

5.5 小结

retry_run 看退出码，retry_match 看输出；两者都只在"全失败"时才分类——中间成功就是 flaky，不算失败但会被看见。

附：三重定位自查清单

新增/修改一篇「hexo主题功能测试」系列文章时，检查以下三项：

#检查项通过标准
①可验证每个功能项有明确的输入 → 期望输出（自动化断言标记或人工核对标准）
②有效果每个功能项描述了渲染后的实际效果（文字描述、示例渲染、或截图）
③会使用每个功能项有语法/配置步骤 + 注意事项（参数顺序、前置条件、常见坑）

快速判断：如果一个功能"只列了名字没说怎么验证"→ 缺 ①；"只列语法不给效果"→ 缺 ②；"没说怎么用或有歧义"→ 缺 ③。
