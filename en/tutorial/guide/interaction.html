Interactions & Visual Effects

This page covers the interaction & visual features of the matery theme: code block enhancements, image lightbox, typewriter, page effects, simplified/traditional Chinese conversion, reading progress, back-to-top, rewards, print styles, audio/video players and charts. Each feature lists its config location and how to use it.

How to read this page: every feature is shown as a pair — Effect → Corresponding config. Look at what it produces first, then copy the YAML below. Every key in the parameter tables appears either on this page or in userConfig/_config.tmp.yml; unverified values are marked “other values unverified”.

Config locations are all in the theme config themes/matery/_config.yml (“theme config” below). Note: in this project the theme config file is overwritten by the userConfig/_config.tmp.yml template during CI builds — sync your changes to the template (see the Installation chapter). Some features have no dedicated config key (back-to-top, print styles) — they are built into the theme and work out of the box.

1.4 Boundaries & conflicts

  • height_limit maps to the CSS variable --code-max-height; when expanded, JS sets the container’s maxHeight to scrollHeight (no longer bounded by that value), and on collapse restores it to empty, back to 450px.
  • copy_btn / show_full / shrink are three independent buttons, combinable freely; turn all off and only a bare code block remains.
  • The language label is only output when language.enable: true; unrecognized languages fall back to language.default.
  • Changing any item in this section requires a clean build to take effect (the cache does not notice config changes).

1.5 Summary

  • Minimum viable: language.enable + copy_btn — two lines are enough.
  • Afraid of exploding long posts: tune height_limit; show_full provides the “expand” bar.
  • Changes don’t apply: suspect the cache first; do a clean build.

4.4 Boundaries & conflicts

  • The page and mouse groups are each single-select: configuring several in one group means only the one named by default takes effect.
  • The two groups persist independently: matery.effect.page and matery.effect.mouse do not interfere; after switching in the panel you must refresh the page for it to apply.
  • Desktop gate: with desktop_only: true, injection happens only when the window width exceeds the BP.fun breakpoint (~992px) and the local visit count is > 1; mobile and first-time visitors do not load it.
  • The legacy standalone sakura / ripples / clicklove enable sections have been removed and no longer participate in injection; add/remove effects by editing the available lists — the panel and runtime adapt automatically.
  • Runtime logic lives in themes/matery/source/js/plugins.js (Matery.plugins.effects); config metadata is injected into window.Matery.effects by themes/matery/layout/_partial/script/effects.ejs.

4.5 Summary

  • Minimum viable: effects.enable + one line page.default to pick an effect.
  • Several in one group does nothing: only default takes effect.
  • Nothing on desktop: check whether the width passes the breakpoint, then the visit count (first visits don’t inject).
  • Want to change your mind: use the floating panel instead of repeatedly editing config.

16.4 Boundaries & conflicts

  • Switch hierarchy is background.enable (master) → each sub enable → panel selection; turning off any level stops rendering.
  • With random: true, images are picked from lightPath / darkPath libraries by light/dark theme; lightNum / darkNum are the available image counts (0-based).
  • The video background’s brightness field is filtered by theme (cover grayscale ≥90 = bright / <90 = dark).
  • Image and video are mutually exclusive (the panel’s matery.bg is single-select); the loading animation is a separate single-select.

16.5 Summary

  • Change the image every time: random: true + library paths and counts.
  • Want to turn off the background area: background.enable: false (the corresponding panel area disappears too).

17.4 Boundaries & conflicts

  • The panel itself is always visible; only the “Effects” and “Background” areas are shown/hidden by effects.enable / background.enable.
  • Font scaling changes --font-scale on <html>; root font size = calc(--font-size-base × --font-scale) (default 16px × 1); styles hardcoded in px do not scale.
  • Display mode shares the same localStorage key as color-schema.js; both entries (menu button / panel) stay in sync.
  • Files involved: template themes/matery/layout/_partial/common/right-floating.ejs; font-size variables in themes/matery/source/css/_pages/_base/base.styl and color-schema.styl.

17.5 Summary

  • Reader self-service: for most preference issues, have readers adjust the panel rather than editing config.
  • Two areas can be hidden: turning off effects.enable / background.enable removes them from the panel.
  • Direct storage access: all preferences live in localStorage; clearing it falls back to config defaults.
