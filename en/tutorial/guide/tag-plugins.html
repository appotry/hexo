Content Tag Plugins

This page summarizes the 14 content tag plugins of the matery theme: note, timeline, tabs, label, button, githubCard, mermaid, pdf, insertmd, wechat_dialog, groupimage, cardurl, admonition, encrypt. Each plugin gives its purpose, syntax, example and effect — examples can be copied directly into a post for testing.

How to read this page: every plugin is shown as matched pairs of Effect → Corresponding source — see the real render first, then copy the Markdown below it. All defaults in the parameter tables come from the actual code in themes/matery/scripts/tags/*.js, not guesses.

Unlike the inline bold-label style of the “Layout & Pages” chapter, this page uses third-level subheadings (minimal example / common variants / full parameters / advanced composition / boundaries & pitfalls / summary) because it needs to host code blocks and live rendering examples.
The first 12 are native theme tags (registered uniformly in themes/matery/scripts/tags/index.js); admonition is provided by the markdown-it-container plugin (7 container types registered in the root _config.yml: warning/note/info/attention/error/tip/hint).
Note: when showing {% xxx %} tag syntax inside a Markdown code block, you MUST wrap it with raw tags (raw paired with endraw), otherwise nunjucks pre-renders it and the build fails with unknown block tag.

Basic Tag Plugins

1. note

Purpose: colored callout blocks inside posts, for warning / success / info / danger emphasis.

Learning path: minimal example → six colors → hiding the icon → collapsible → nesting → full parameters → boundaries & pitfalls → summary

1.1 Minimal example

No keyword at all — just a grey-bordered callout. The structure is only “opening tag + content + closing tag”.

Effect:

This is the simplest callout.

no-icon is a modifier, not a color. It occupies the second keyword slot and can be swapped with the color order.

1.4 Collapsible

Any remaining argument after the first two keywords is joined into the collapse title and output as <details><summary>.

Effect:

Click to expand: why a static site is enough

A static site has no server, but build-time snapshots provide most dynamic capabilities.

Trade-offs

  • Content updates require a rebuild
  • Search is a local index, not a full-text search service

Corresponding source:

Both the title and the body go through Markdown — the title can be bold, and the body can hold lists and code. But do not write ### subheadings inside the note body: they render as real headings and enter the page TOC.

1.5 Nesting

The body goes through Markdown rendering, so any tag can be nested inside.

Effect:

Composition example

Nested note

A note can nest another note; the inner one uses its own color.

Corresponding source:

1.6 Full parameters

Arguments are split by spaces; note.js loops over at most 2 keywords as CSS classes, and everything else is joined into the collapse title.

PositionParameterRequiredDefaultDescription
1–2color keyword❌nonedefault / primary / info / success / warning / danger
1–2no-icon❌nonehides the left icon; interchangeable with the color position
3+collapse title❌noneall non-keyword arguments are joined into <summary>, rendered as Markdown
bodycontent❌empty stringrendered as Markdown, may nest other tags

All possible values: 6 colors + 1 modifier no-icon (not a color, only hides the icon).

Alias: {% subnote %} registers the same function as {% note %} (two tag.register lines in index.js point to the same postNote); behavior and styles are identical — it is not a “secondary” note.

1.7 Boundaries & pitfalls

CaseBehavior
First word is not a keyword (e.g. {% note hint text %})no color class is added; that word becomes the collapse title → you get an uncolored collapsible block, not a plain block
Writing 3 color keywordsonly the first 2 are used; the 3rd becomes the collapse title
Misspelled color (Warning in caps)case-sensitive → not treated as a keyword; becomes the collapse title with no color
Empty contentoutputs an empty div, no error
Forgetting {% endnote %}build fails with unclosed tag
Wanting a plain block but writing a titleimpossible — any non-keyword argument triggers collapsing; move the text into the body
Mixing with ::: containersdifferent output: the tag is <div class="note primary">, the container is <div class="note"> (CSS already distinguishes them with attribute selectors)

1.8 Summary

  • Most used: note info / note warning — two or three words are enough
  • Want it collapsed: write the title right after the color
  • Want a plain color block without an icon: add no-icon
  • Want nesting: keep writing tags in the body (remember to close them in pairs)

2. timeline

Purpose: show events / version logs / growth history in time order — a vertical line with dots connecting dated nodes.

Learning path: minimal example → no title and color → Markdown inside nodes → full parameters → boundaries & pitfalls → summary

2.1 Minimal example

One title plus one node is a complete timeline. A node is wrapped by <!-- timeline date --> and <!-- endtimeline -->.

Effect:

Theme feature evolution

Corresponding source:

2.2 No title

The first argument of timeline (before the comma) is the overall title; when the whole argument is omitted there is no overall title and nodes are listed directly.

Effect:

2026-07

  • Comment architecture optimization (comment: waline)
  • Fixed the MIME style error for href=/

Corresponding source:

2.3 Color and Markdown inside nodes

The second argument is a class name appended to div.timeline (green / blue / red / orange etc. — decided by CSS); both the title and node content go through Markdown.

Effect:

v13.27 release notes

v13.27 released

The Douban card was changed to a local implementation; covers are downloaded at build time.

Corresponding source:

2.4 Full parameters

timeline.js joins the arguments with join(' ') and splits on ,: args[0] is the title, args[1] is the color class name (no trimming — writing title, green yields a class name with a leading space; it still displays fine but is untidy).

PositionParameterRequiredDefaultDescription
arg 1 (before comma)overall title❌noneomitted = no overall title; rendered as Markdown
arg 2 (after comma)color class name❌noneappended to .timeline; valid values are decided by theme CSS (green / blue / red / orange etc.)
bodynode blocks✅—each node = <!-- timeline node title --> + content + <!-- endtimeline -->

Node titles also go through Markdown (links, bold, inline code are fine). With no node block, only an empty timeline container is output.

2.5 Advanced / composition

  • Node content can contain further tags (e.g. {% label %}, {% button %}) because node content is rendered as Markdown.
  • The number of nodes is unlimited; timeline.js matches globally with a regex and outputs them in order of appearance.
  • The timeline is not a semantic <time> structure — dates are just node title text, and ordering depends entirely on the order you write (it never sorts by date).

2.6 Boundaries & pitfalls

CaseBehavior
No newline after the node marker (<!-- timeline 2026 -->content on the same line)the regex requires \n right after --> → that node is silently dropped
<!--timeline 2026--> (missing space after timeline)the regex requires timeline with a space → no match, node lost
Forgetting <!-- endtimeline -->all following content is swallowed into the previous node, or the whole node is lost
Title contains a commasplit(',') treats the second half as the color → title truncated
Wrong colorthe class name is still output, but no matching CSS exists, so it falls back to the default color
Just want a plain listskip timeline and write a Markdown list — lighter

2.7 Summary

  • Remember two things: node markers must be on their own line, and endtimeline must be closed
  • Title is optional: omit the argument when you don’t want an overall title
  • Color is a CSS class name; a wrong value doesn’t error but has no effect

3. tabs

Purpose: multi-tab content switching, great for categorized display / step-by-step instructions / comparisons.

Learning path: minimal example → choosing the active tab → icons in tab titles → full parameters → boundaries & pitfalls → summary

3.1 Minimal example

The first argument is the required unique name (used to generate DOM ids); omitting it makes the build error and outputs an empty string.

Effect:

  • Pros
  • Cons
  • Full-featured: content tags cover 10+ plugins
  • Flexible config: every feature independently toggleable
  • Many config options, learning curve at first
  • Some features depend on external CDN

Corresponding source:

3.2 Choosing the active tab

The second argument is the active index, starting at 1; omitted or 0 activates the first tab.

Effect:

  • First
  • Second

Not active by default.

Shown by default when the page opens.

Corresponding source:

3.3 Icons in tab titles

Append @icon in the tab title to add a Font Awesome icon: text before @, “prefix:icon-name” after @.

Effect:

  • Intro

@fas:info-circle → <i class="fas fa-info-circle">

Corresponding source:

3.4 Full parameters

tabs.js first does args.join(' ').split(','): args[0] = name, Number(args[1]) || 0 = active index.

PositionParameterRequiredDefaultDescription
1 (before comma)unique name✅—when missing, hexo.log.error is called and an empty string is returned (nothing shows on the page)
2 (after comma)active index❌0 (= first)counted from 1; non-numeric values are treated as 0
bodytab blocks✅—each tab = <!-- tab title --> + content + <!-- endtab -->

Icon prefix values (processIcon’s prefixMap): fas / far / fal / fad / fab, plus aliases solid→fas, regular→far, light→fal, duotone→fad; with no prefix it defaults to far (regular).

Alias: subtabs and subsubtabs register the same function; syntax and behavior are identical (the names only express a nesting convention — they do not produce nested styles).

3.5 Advanced / composition

  • Each tab’s content area is rendered as Markdown independently and can hold lists, tables, code, and other tags.
  • DOM structure: <div class="tag-common tabs" id="name-lowercased-spaces-to-dashes"> + ul.nav-tabs + div.tab-content; switching is done by front-end JS adding .active.
  • The name is converted into an id: lowercase + spaces replaced by -; Chinese characters are kept as-is.

3.6 Boundaries & pitfalls

CaseBehavior
No name[Tabs] Missing required tab name error log + the whole block outputs nothing
Two tabs on the same page with the same nameduplicate ids → clicking may switch the wrong group
Active index out of range (e.g. ,9 with 3 tabs)no tab gets .active → all collapsed, must be opened manually
Content written on the same line after <!-- tab title -->the regex requires \n after --> → that tab is dropped
Forgetting <!-- endtab -->following content is swallowed into the previous tab
Name contains a commatruncated by split(','); the second half becomes the active index

3.7 Summary

  • Name is required, and unique on the page
  • Content areas are full Markdown and can nest anything
  • Active index starts at 1

4. label

Purpose: inline colored mini labels for keywords / status / category annotations.

Learning path: minimal example → six colors → full parameters → boundaries & pitfalls → summary

4.1 Minimal example

The argument order is counter-intuitive: color@text — color before @, text after @.

Effect:

This site is built with Hexo and themed with matery.

Corresponding source:

4.2 Six colors

Effect:

Default Primary Success Info Warning Danger

Corresponding source:

4.3 Full parameters

label.js: args.join(' ').split('@') → classes = args[0] || 'default', text = args[1] || '', output as <span class="label label-<classes>">.

PositionParameterRequiredDefaultDescription
before @color❌defaultdefault / primary / success / info / warning / danger
after @text✅empty stringplain text (not Markdown; bold/links are not rendered)

When the text is empty, label.js calls log.warn('[Matery] Label text must be defined!') and renders an empty span.

4.4 Boundaries & pitfalls

CaseBehavior
Only {% label text %} (no @)text is empty → renders an empty label + build warning; text is treated as the color class
Misspelled color (label-warningx)outputs class="label label-warningx"; no matching CSS → only the base .label style remains
Text contains @ ({% label info@a@b %})split('@')[1] takes only a; b is dropped
Want bold/links inside the labelnot supported; text is output verbatim
Multiple on one linesupported, separate with spaces (see 4.2)

4.5 Summary

  • Always color@text — forget the @ and you get an empty label
  • Text does not support Markdown
  • Values outside the 6 colors don’t error but have no styling
