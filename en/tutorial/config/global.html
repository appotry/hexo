Global Configuration

This page covers the blog’s global configuration: site info, URL & permalinks, theme basics (Logo/Favicon), banner background, and the CDN mechanism. This is the foundation of the whole blog — every other config chapter builds on top of it.

Config has two layers: site config _config.yml (Hexo core + plugins) and theme config (layout/appearance/interaction). In this project the theme config file is overwritten by the userConfig/_config.tmp.yml template during CI builds — edit the template for theme config changes (see the Installation & Theme Config chapter). Unless marked “root config”, everything on this page is theme config.

How to read: every section follows “How to enable → Common options → All tunable keys → Boundaries & conflicts”. See the effect first, then the corresponding config that produces it — copy and use.

2. URL & Permalinks

Purpose: the site root URL and post link format. This blog uses abbrlink (CRC32 + hex) for short links, permanent after publishing.

Learning path: How to enable → Common options → All tunable keys → Boundaries & conflicts

2.1 How to enable

Effect: post links look like https://blog.17lai.site/posts/8f9792ab/ — short and unrelated to the title; retitling a post doesn’t change its link.

Corresponding config (root config _config.yml):

2.2 Common options

① Site root URL

Effect: canonical, sitemap and RSS absolute links are prefixed with it; a wrong value makes every outbound link point at the wrong domain.

Corresponding config:

② Link format

Effect: post URLs become /posts/<abbrlink>/; changing the format breaks all existing links.

Corresponding config:

③ Hash algorithm and representation

Effect: crc32 + hex produces 8-character hex short links; switching algorithms only affects new posts, since old abbrlinks are already written into front-matter.

Corresponding config:

④ Whether drafts get short links

Effect: with drafts: true drafts also get an abbrlink; the default false generates it only on publish.

Corresponding config:

2.3 All tunable keys

KeyTypeDefaultOptions/RangePurpose
urlstring—full site URLabsolute-link base
permalinkstring—path template, e.g. posts/:abbrlink/post link format
abbrlink.algstringcrc16crc16 / crc32hash algorithm
abbrlink.repstringdecdec / hexrepresentation
abbrlink.draftsboolfalsetrue / falsegenerate for drafts
abbrlink.forceboolfalsetrue / falseforce recompute (ignores cache, use with care)
abbrlink.writebackboolfalsetrue / falsewrite back to source files

2.4 Boundaries & conflicts

  • writeback: false (since 2026-09-22) means the plugin does not write back to source files — it was disabled because a resident hexo server that reads a file mid-edit (empty) would clobber the source with a truncated object (see docs/EXPERIENCE.md §55).
  • abbrlink is written into each post’s front-matter on first generation and stays fixed thereafter, so renaming posts won’t break old links.
  • url is the base of all absolute links (canonical, sitemap, RSS) — it must match the deployment domain in production.
  • force: true recomputes every short link, which invalidates all published links — only use it for a deliberate migration.

2.5 Summary

  • Minimum viable: url + permalink
  • Short links: alg: crc32 + rep: hex
  • Don’t enable force: it kills old links
  • Don’t enable writeback: the resident server can clobber source files

5. CDN Mechanism

Purpose: serve all static assets (JS/CSS/images) via CDN. This project uses jsDelivr + placeholder injection: templates contain {cdnPathVersion} and other placeholders, replaced with real CDN URLs at CI build time.

Learning path: How to enable → Common options → All tunable keys → Boundaries & conflicts

5.1 How to enable

Effect: after building, JS/CSS links in the pages point to jsDelivr versioned paths and the browser loads from the CDN; a direct local hexo generate still keeps the placeholders (unreplaced).

Corresponding config (theme config):

5.2 Common options

① Versioned CDN path

Effect: asset URLs carry a version like @1.1, so browsers fetch new files after a release.

Corresponding config:

② latest path

Effect: always points at the latest version (not recommended in production — cache is uncontrollable). Currently commented out and not enabled.

Corresponding config:

③ Three asset domains

Effect: JS/CSS, images/media and other resources are loaded from their own domains.

Corresponding config:

5.3 All tunable keys

KeyTypeDefaultOptions/RangePurpose
jsDelivr.urlstring—URL containing {cdnPathVersion}versioned CDN path
jsDelivr.latesturlstring—URL containing {cdnPathLatest}latest path (currently commented)
cdn.urlstring—contains {cdnUrl}JS/CSS CDN
cdn.mediaUrlstring—contains {mediaUrl}image/media CDN
cdn.resUrlstring—contains {resUrl}resource CDN (default https://cfblog.17lai.site)

Placeholders and build-time replacement (done by userConfig/_config.tmp.yml + tools/cicd.sh sed):

PlaceholderReplaced withExample
{cdnPathVersion}jsDelivr versioned pathhttps://cdn.jsdelivr.net/gh/appotry/hexo@1.1
{cdnPathLatest}latest CDN pathhttps://cdn.jsdelivr.net/gh/appotry/hexo@latest
{urlVersion}file version number?v={urlVersion}
{cdnUrl} / {mediaUrl} / {resUrl}CDN domainshttps://cfblog.17lai.site

5.4 Boundaries & conflicts

  • When writing config here you don’t need to care about placeholders — keep {xxx} as-is, CI handles it.
  • Release timing: after changing JS/CSS run tools/cicd.sh -r "feature" to bump the version (tools/.VERSION), otherwise browsers/PWA cache the old version; content-only changes use -c or -d.
  • A direct hexo generate does not replace placeholders, so assets 404 — you must go through the CI scripts.

5.5 Summary

  • Minimum viable: leave the template placeholders untouched
  • Changing assets: must use -r to bump the version
  • Don’t use latest: production cache is uncontrollable
  • Local 404: CI injection was skipped
