Sidebar Widgets

This page explains sidebar & homepage widgets: page-level statistics widgets (tag cloud/word cloud/category radar/archive/charts), the Live2D mascot, and the music player. The first two are auto-rendered by the theme; the latter two have dedicated config.

The authoritative source of the theme config is userConfig/_config.tmp.yml (it overwrites the theme config at CI time).

How to read: every section follows “How to enable → Common options → All tunable keys → Boundaries & conflicts”. Look at the effect first, then the corresponding config that produces it — copy and use.

1. Page-level Widgets (auto-rendered)

Purpose: the following widgets are rendered automatically by the theme generators per page — no config needed, they update with the content.

Learning path: How to enable → Common options → All tunable keys → Boundaries & conflicts

1.1 How to enable

Effect: open /tags/ and you see a chip-style tag list plus a canvas word cloud (font size ∝ post count); open /categories/ and you see a category cloud plus a radar chart; open /archives/ and you see a timeline and a calendar. No config change is needed — create content and they appear.

Corresponding config: none (the widgets are mounted by the layout templates).

1.2 Common options

① Adjust the tag cloud content

Effect: the words and font-size distribution of the tag list and word cloud follow the post tags; add a tag and the word cloud gains an entry.

Corresponding config (post front-matter):

② Adjust the category radar

Effect: the radar axes and values follow categories; the deeper the category hierarchy, the finer the distribution.

Corresponding config (post front-matter):

Widget list (corresponding to the themes/matery/layout/_partial/widget/ directory):

1.4 Boundaries & conflicts

  • These widgets are mounted on their layouts; page data comes from the site content itself.
  • To “configure” them you essentially adjust the content structure (tag naming, category hierarchy), or edit the themes/matery/layout/_partial/widget/*.ejs templates (advanced customization).
  • With no posts the word cloud/radar shows an empty figure — that is not a config error.

1.5 Summary

  • Minimum: configure nothing, just publish posts
  • Change the distribution: tune tag/category naming and hierarchy
  • Change the style: edit _partial/widget/*.ejs
  • Empty figure: first confirm there are published posts

2.4 Boundaries & conflicts

  • Models and tips are configured under source/live2d/ (static models) and the waifu-tips files, managed independently of the theme config.
  • The class: menu-2d-* values in menu items (e.g. menu-2d-home) are positioning selectors for the mascot’s tip box (see the Navigation Menu & Homepage chapter).
  • Full add/remove/switch procedures for models: see the blog’s live2d maintenance docs.
  • Dual runtime: Cubism 2 (live2d.min.js) and Cubism 5 (live2dcubismcore.min.js) coexist; autoload.js loads the appropriate version based on model metadata (cubism2Path / cubism5Path).
  • Local models: models and manifests are located at source/live2d/model/ and source/live2d/model_list.json.
  • Actual config keys: theme config has only the live2dWidget.enable switch; the autoload script path is libs.js.live2dAutoload → /libs/live2d/autoload.js; runtime assets (autoload.js / waifu-tips.js / waifu.css) live in themes/matery/source/libs/live2d/.
  • Tips are configurable: yes — autoload.js points to waifu-tips.json via waifuPath; edit that file to customize tips.
  • Dark mode adaptation: waifu.css supports both manual dark mode ([data-user-color-scheme="dark"]) and system preference (prefers-color-scheme: dark).
  • Loading threshold: layout/_partial/script/live2d.ejs only loads when window width > BP.fun AND visit count > 2.

2.5 Summary

  • Minimum: live2dWidget.enable: true
  • Change the character: edit model_list.json + model/
  • Change the lines: edit waifu-tips.json
  • Not showing: check the window-width and visit-count thresholds first

3.4 Boundaries & conflicts

  • Fill id with the platform’s playlist/song ID (NetEase playlist IDs are visible in the page URL).
  • The player remembers user settings — after a user adjusts volume manually, the volume default no longer applies.
  • Homepage music and music page musics are two separate configs and do not inherit from each other; changing one does not affect the other.
  • title only works in non-fixed mode (a fixed bar has no title bar).

3.5 Summary

  • Minimum: enable + server + type + id
  • Site-wide background music: musics.fixed: true
  • Don’t want it to play automatically: autoplay: false
  • Volume has no effect: the user adjusted it manually — expected behavior
