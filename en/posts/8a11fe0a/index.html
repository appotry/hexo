The theme’s natively registered tags live in themes/matery/scripts/tags/ (unified registration in index.js).
Automated tests assert the rendered markers noted below.

1.6 Full parameters

Arguments are split on spaces. At most the first 2 keywords become CSS classes; all remaining arguments are joined into the collapsible title.

1.7 Boundaries & pitfalls

CaseBehaviour
First word is not a keyword (e.g. 提示内容)No color class is added; that word becomes the collapse title → you get a colorless collapsible block, not a plain block
Three color keywords writtenOnly the first 2 are taken → class="note info success", the third becomes the collapse title
Color misspelled (Warning with a capital)Case-sensitive → treated as a non-keyword, becomes the title and has no color
Empty contentEmits an empty div, no error
Closing tag forgottenThe build reports unclosed tag
Wanted a plain block but wrote a titleImpossible — any non-keyword argument collapses the block. Move the text into the body
Mixed with the ::: containerDifferent output: the tag emits <div class="note primary">, the container emits <div class="note"> (CSS distinguishes them with attribute selectors)

1.8 Summary

  • Most used: note info / note warning — two or three words is enough
  • Want it collapsible: write the title right after the color
  • Want a solid block without an icon: add no-icon
  • Want nesting: keep writing tags in the body (remember to close them in pairs)

7.5 Boundaries & pitfalls

CaseBehaviour
specific: true but front-matter lacks mermaid: trueThe theme emits no script at all → blank diagram, no console error (the most invisible pitfall)
theme=dark inside the tagOnly adds an HTML attribute, the diagram theme does not change

  • A syntax error does not fail the build: that block is just blank — check the console for a parse error

Coexistence with encrypted fragments (important): markmap’s four scripts (d3 / markmap-view / markmap-toolbar / init) are localized by an after_render:html filter. Pages containing {% encrypt %} use a serial onload-chain loader instead of <script defer> — because the HTML spec says a dynamically inserted <script> ignores defer (its async defaults to true). When the hbe decryption flow re-inserts them, they execute in download-completion order, exactly inverting the dependency chain (init at 1.8KB finishes first → window.markmap undefined; d3 at 280KB finishes last → markmap-view throws d3 is not defined). Static pages keep defer (parallel download, better first paint). Full root cause and debugging lessons: docs/EXPERIENCE.md §58.

Pitfall 1: double section numbering

Symptom: headings render as “1. 1. Overview” (two numbers).

Cause: theme CSS auto-numbers h2–h6 by default, which stacks on top of hand-written numbers (e.g. ## 1. Overview).

Fix: pages with hand-written numbering add closeAutoTocNum: true in front-matter; pages without hand-written numbering must not add that field.

This article already sets closeAutoTocNum: true correctly.

Pitfall 5: config changes require a clean build

Symptom: after changing tag-plugin configuration (e.g. post.mermaid.enable, live2dWidget.enable, sharejs.enable), the page does not change.

Cause: Hexo’s cache does not detect configuration changes automatically.

Fix: after changing config you must run npm run clean && npm run build.
