This article serves as both a complete usage tutorial for matery theme content tag plugins and an automated test sandbox.
The theme’s native tags are registered in themes/matery/scripts/tags/ (unified registration via index.js).
Automated tests assert the rendered markers indicated below.

1. Note

Purpose

Colored callout blocks inside posts, for warning / success / info / danger emphasis.

Syntax

  • Color (optional, default default): default / primary / success / info / warning / danger
  • Alias: {% subnote %} (secondary note)

All Colors Example

default default note — plain hint

primary primary note — key emphasis

success success note — operation complete

info info note — supplementary

warning warning note — caution

danger danger note — serious warning

Effect

Colored rounded cards with a left color bar + icon (success ✓ / warning ⚠ / danger ✕).

Test assertion: page contains class="note" marker (6 colors, one each).

2. Timeline

Purpose

Show events / version records / growth history in chronological order.

Syntax

  • Title: overall timeline title
  • Color (optional): green / blue / red / orange etc.
  • Time nodes: <!-- timeline date --> separates each event

Example

Theme Feature Evolution

2026-08

  • Added content tag test page (note/timeline/tabs/label complete tutorial)
  • Gallery data refactor (galleries.yml three forms)
  • Unified lightGallery image viewer library

2026-07

  • Comment architecture optimization (comment: waline)
  • Fixed href=/ MIME style error

Effect

Vertical timeline with dot markers, color themes supported, titles rendered with Markdown.

Test assertion: page contains timeline marker + 3 time nodes.

3. Tabs

Purpose

Multi-tab content switching, great for categorized display / step-by-step instructions / comparisons.

Syntax

  • Unique name: required, used to generate ids (spaces become -)
  • Active index: optional, default 1 (first tab activated)
  • Tab titles: <!-- tab title --> defines each tab

Example (first tab active by default)

  • Pros
  • Cons
  • Best For
  • Full-featured: content tags cover 10+ plugins
  • Flexible config: every feature independently toggleable
  • Performance: lazy loading + CLS placeholders
  • Many config options, learning curve at first
  • Some features depend on external CDN
  • Tech blogs: code / tutorials / comparisons
  • Personal blogs: galleries / projects / history

Effect

Materialize tabs style, click to switch, active tab highlighted.

Test assertion: page contains nav-tabs marker + 3 tabs.

4. Label

Purpose

Inline colored mini labels for keywords / status / category annotations.

Syntax

  • Color (optional, default default): default / primary / success / info / warning / danger
  • ★ Note the parameter order: color BEFORE @, text AFTER @ (source uses split('@'), classes=args[0], text=args[1])

All Colors Example

Default Primary Success Info Warning Danger

Effect

Inline rounded colored labels, text on white or colored background.

Test assertion: page contains class="label" marker (6 colors).

5. Button

Purpose

CTA buttons inside posts, for links / downloads / action entries.

Syntax

  • ★ Link is the FIRST argument (source: url=args[0], text=args[1])
  • Link: required, target URL (relative path / allowed)
  • Text: button display text
  • Icon (optional): Font Awesome icon name (e.g. home, github; fa fa- prefix auto-added)
  • title (optional): hover tooltip text (not a color!)
  • Alias: {% btn %}

Example

Home GitHub About Text-only button

Effect

Materialize-style buttons with icon + ripple click effect.

Test assertion: page contains btn marker (≥4 buttons).

6. GitHub Card

Purpose

Show a GitHub repo info card (repo name / description / stars / forks).

Syntax

  • user: required, GitHub username
  • repo: required, repository name
  • Optional params (advanced): width / height / theme / align

Example

Effect

Repo card: name + description + stars / forks, click to visit the repo. Depends on GitHub API (falls back to a link on failure).

Test assertion: page contains github-card or repo name link marker.

Render Mermaid diagrams (flowcharts / sequence diagrams / class diagrams etc.).

Front-matter Config (important)

Also requires enabling in the theme _config.yml:

Syntax

Mermaid renders to SVG diagrams, adapting to dark mode (theme already handles it).

10. WeChat Dialog Card

Purpose

Render a WeChat chat interface card, for dialog examples / support scenarios.

Syntax

  • Line format: lines starting with User: = right-side user bubble; Assistant: = left-side assistant bubble
  • Supports: multi-line content, Markdown rendering (bold / lists etc.)
  • Alias: {% wd %} equals {% wechat_dialog %}

Example

Hi, I'd like to learn about the matery theme

Sure, how can I help?

What features does the theme support?

Content tags, galleries, search, comments and 20+ more features

Effect

WeChat-style chat bubbles, left/right split, avatar + bubble.

Test assertion: page contains WeChat dialog container marker (.chat-container).

11. Group Image

Purpose

Display multiple images in a row/column grid layout (auto column splitting).

Syntax

  • First parameter: number of images (2–10)
  • Second parameter (optional): layout (e.g. 2-1 means 2 on the first row, 1 on the second)
  • Images: standard Markdown image syntax inside the tag body
  • Alias: {% gi %} equals {% groupimage %}

Example (3 images, 2+1 layout)

Effect

Image grid layout (2+1 columns), zoom on hover.

Test assertion: page contains group-image container marker.

12. URL Card (cardurl)

Purpose

Show a summary card for a link (title, description, icon), for recommended links / cited resources.

Syntax

  • Params: bracket [key=value] format
    • url required, target link
    • title optional, card title (defaults to url)
    • desc optional, description text
    • avatar optional, icon image URL

Example

https://github.com/appotry/hexo
undefined

Effect

Link card: site icon + title + description, click to jump.

Test assertion: page contains URL card container marker (.card-url-wrapper).

13. Admonition (markdown-it-container)

Purpose

Render callout containers using the ::: type syntax via the markdown-it-container plugin (warning / note / info / attention / error), distinct from the note tag.

Syntax

  • Types: warning / note / info / attention / error etc.

Example

This is a warning container — content that needs attention!

This is a note container — supplementary info.

This is an info container — informational.

This is an attention container — caution.

This is an error container — serious error.

Effect

Callout containers with a left color bar + icon + light background.

Test assertion: page contains admonition container marker.

14. Encrypt Fragment Tag ({% encrypt %})

Purpose

Encrypt a segment of markdown content within a post. Enter the password to decrypt and reveal the content. Each fragment has its own independent password.

Syntax

ParameterRequiredDescription
password✅Decryption password (Hexo auto-strips quotes)
title (second quoted param)❌Prompt text shown above the password input
description (third quoted param)❌Placeholder text shown inside the input field

Example (test fragment)

Private Content

Effect

  • After rendering, the segment becomes an encrypted container (password input); enter test-secret to decrypt and reveal
  • Nested tag support: fragments can contain {% note %} and other tags (Method Y: after_post_render secondary rendering, verified working)
  • No plaintext leakage: the rendered HTML contains no segment plaintext (encryption happens on the final HTML)
  • No re-entry needed: after decryption, refreshing within 1 day skips the password prompt (stores derived dk, not the password, with TTL mechanism)

Automated Testing

Integration test tools/tests/encrypt-integration.test.js (L2n) covers: S1 no plaintext leakage / I1 fragment decryption / I1b internal note rendering / I1c markdown bold / S2 dk storage without password.

Wiki Full-Page Encryption (docs-sidebar)

Wiki document pages (layout/wiki.ejs) support full-page encryption: configure encrypt_password in the sidebar data source (source/_data/docs-sidebar.yml) to encrypt all pages under that wiki, enter password to decrypt and render.

Cross-page sharing: after decryption, the derived key (dk) is stored in localStorage; other pages under the same wiki auto-decrypt without re-entering the password.

Test assertion: L2y (wiki encrypted page decryption) + L8 8c (encrypted wiki accessible).

Unified Post-Decryption Refresh

After decrypting encrypted content, page components need re-initialization (before decryption the DOM contains only ciphertext). The unified trigger point: hbe-bundle onSuccess callback (shared across post / gallery / wiki / fragment); each listener keeps only its specific handling; config keys with the encrypt_ prefix are skipped during sidebar rendering (not shown as table of contents items).

ComponentPost-Decryption Action
Code blockscodeWidget() scans new pre elements and generates toolbar
Image lightboxarticleInit() wraps img elements → lightGallery
Mermaidevents.refresh() re-renders (idempotent)
LayoutrefreshLayout() re-arranges

See the Layout chapter §8 “Unified Post-Decryption Refresh” for the full table. Test assertion: L2y (post-decryption component initialization).
