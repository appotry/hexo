This article is both a complete usage tutorial for the matery theme’s layout and page features and an automated testing playground.
Coverage: post layout features, sidebar widgets, responsive breakpoints, galleries, search, comments, dark mode, encryption, RSS/sitemap, PWA.
Automated tests (tools/tests/release-test.sh) assert the rendering markers labeled below.

1. Post Layout Features

Purpose: Display prev/next post cards at the bottom of a post to guide continuous reading.

Configuration (theme _config.yml):

Effect: Two cards at the end of the post showing adjacent posts’ titles + thumbnails, with a gradient background on hover.

Test assertion: The post page contains the #prenext-posts container.

Purpose: Show copyright and license information at the bottom of a post, noting the author and reprint rules.

Configuration (theme _config.yml):

Effect: A grey copyright card at the bottom of the post with author, link, and license rows.

Test assertion: The post page contains a copyright notice container (#copyright or .post-copyright).

Test assertion: The post page contains the .tgCard ad container.

1.6 Word Count & Reading Time

Purpose: the post header article-info shows the per-post word count and estimated reading time; the footer shows the site-wide total.

Configuration (theme _config.yml, post section):

Implementation (themes/matery/scripts/helpers/wordcount.js): three built-in helpers replace the former hexo-wordcount plugin — same names and signatures, so no template changed:

HelperPurpose
wordcount(page)per-post count (CJK characters + English words)
min2read(page)reading time in minutes = floor(count / (awl × wpm)) + 1
totalcount(site)site-wide total (posts + wiki pages; i18n duplicates de-duplicated; encrypted posts counted by plaintext post.origin)

Effect: article-info shows “word count · reading time”; the footer shows the site-wide total (wiki pages and encrypted posts included).

Test assertion: posts expose the article-info word-count / reading-time markers; the three helpers’ behaviour is covered by tools/tests/unit/helpers.test.js.

⚠️ Historical bug (fixed 2026-09-22): the old default awl: 2 / wpm: 60 equals 120 chars/min — tuned for English — so a 520-character Chinese post showed 5 min; with the new awl: 1 / wpm: 300 the same post shows 2 min.

4. Content Width Unification (Added 2026-09-07)

Design Principle

“Percentage + Max-width”: Content area width: 90% (relative to screen) + max-width steps (readability limit). Not pure 90% — at 4K, 90% = 3456px is unreadable.

Width Steps (_variables/base.styl)

BreakpointStandard (single-column)Wide (multi-column)
FHD 993-1920px1125px1250px
2K 1921-2560px1525px1750px
4K 2561px+1525px (capped)2250px

Selection Rules (mixin content-container(wide))

  • Single-column (content without sidebar): content-container() → standard width
  • Multi-column (content + sidebar/TOC): content-container(true) → wide width
  • No hand-written max-width in layout (unified via mixin)

Implementation effect: Wiki (multi-column) 4K content column 899px → 1500px (+67%); same width steps as post-container.

Automated testing: tools/tests/content-width.test.js (L2m) covers: W1 4K wiki==post-container / W3 FHD / W4 2K / W5 single-column capped at 1525px.

FA Resource Version Stamp ({urlVersion})

Purpose: Ensure browsers/CDN fetch new resources after a version release, avoiding stale caches.

Mechanism: Resource URLs carry a version stamp placeholder {urlVersion} (e.g., /libs/awesome/webfonts/fa-solid-900.woff2?v=13.13). During build, tools/cicd.sh sed-replaces it with the actual version number (from tools/.VERSION).

Affected resources (userConfig/_config.tmp.yml, static_prefix.libs section):

ResourceConfig KeyExample
FA WebFontfaBrands/faRegular/faSolid/libs/awesome/webfonts/fa-solid-900.woff2{urlVersion}
Theme CSSmatery/mycss/main/css/main.css{urlVersion}
Highlight CSShighlight/highlightDark/css/highlight.css{urlVersion}

No manual action required: Version is injected automatically by CI. Local preview (hexo server) does not replace the placeholder; resources have no version suffix (functionality unaffected).

⚠️ Do not manually edit the {urlVersion} placeholders in themes/matery/_config.yml — that file is a build artifact overwritten by userConfig/_config.tmp.yml during CI.

5. Multilingual Fallback Mechanism (Added 2026-09-08, Revised 2026-09-10)

Language Configuration (preference section)

  • default_lang: Default language (no prefix path), shared by all components
  • fallback_lang: Fallback intermediate layer — when the requested language doesn’t exist, fall back to this language first
  • lang_meta: Language capability table (9 languages) + enabled switch (disabled languages don’t generate fallback pages / don’t appear in dropdown)

Fallback Chain (Three Layers)

Behavior by Page Type (Revised 2026-09-10)

Page TypeMultilingual VersionNotice Banner
Post✅ If translation exists, use it; if not, generate via fallback chain✅ Show “xx doesn’t exist, displaying yy language version”
Wiki page✅ Same as above✅ Same as above
Aggregation page (tag/category/archive)✅ Generate per enabled languages❌ Generate only, no notice
Standalone page (about/musics/movies/friends/msg/bb/galleries etc.)✅ Generates /{lang}/{page}/ (UI text goes through languages/{lang}.yml i18n)❌ None
Homepage✅ /en/, /en/page/N/❌ None

Standalone pages (including gallery sub-pages and historical pages with layout:'post' in the pages collection, such as dash) are generated by standalone-page-generator.js using an exclusion method (layout ∉ {wiki, tags, categories, 404} → generate; new standalone pages are automatically covered without registering to a list).

Real Translation Mapping (post / wiki)

Translation files share the same filename as the default language, placed in the language subdirectory:

TypeTranslation Source Pathfront-matter
Postsource/{lang}/_posts/{same-name}.mdKeep the same abbrlink + add lang: en
Wikisource/{lang}/docs/{same-name}.mdSame (wiki pages have no abbrlink, mapped by same-name path)

Chinese-English association has two modes: with abbrlink plugin → same abbrlink associates; without plugin → same-name file association (with filesystem fallback check). With real translation → generates /{lang}/posts/{abbrlink}/ real content page; without translation → fallback chain generates.

Note: Hexo natively only recognizes source/_posts/ (en/_posts/ is ignored); article translations are generated by the theme’s i18n-post-generator.js.

Title i18n (page_title_i18n, 2026-09-10)

<title> and the cover headline (bg-cover-content.ejs) share page_title_i18n from scripts/helpers/page-title.js: tags/categories/about map by title, the rest map by layout to i18n keys; when it returns null the caller falls back to the original title — multilingual page titles switch with the language.

Client-Side Language Strategy (Scheme A: site-wide follow, 2026-09-10)

ScenarioBehavior
First visitNo local preference and browser language matches an enabled language → popup asking to switch; if accepted, remember and redirect; if rejected, remember default language (won’t ask again)
Panel switchLanguage dropdown selection → write local preference + redirect to corresponding language version
Page load / refreshHas local preference → load corresponding language version directly (head.ejs inline redirect, before render with no flash); crawlers skipped (SEO); no multilingual version path skipped (prevent 404)
Panel displayLanguage dropdown shows local preference (localStorage.wiki_lang)

Language Prefix Rules (url_for_lang)

Resources (css/js/libs/medias/images/fonts etc.) and static files (xml/txt/json etc.) do not get language prefixes; all other content paths always get the prefix. Exemption rules come from a single source: scripts/utils/url-lang-blacklist.js. Standalone page navigation thus carries the /en/ prefix pointing to the corresponding language version.

Implementation Effect

Visiting /de/docs/setup/ (de enabled, no translation): if en translation exists → content uses en + notice banner “de doesn’t exist, displaying en”; if no en → content uses zh-cn + notice banner. Standalone page navigation (url_for_lang) doesn’t add language prefix, always points to default language version.

Automated testing: tools/tests/lang-fallback.test.js (L13) covers fallback chain 4 levels + configuration compatibility/filtering/validation (13 assertions); tools/tests/release-test.sh L2x covers MATERY_LANG injection / fallback pages / 9 standalone pages multilingual (including gallery sub-pages and dash) 200 / aggregation page multilingual; tools/tests/unit-standalone.test.js (L13, 22 assertions) covers standalone page exclusion judgment + language prefix exemption; tools/tests/lang-client-strategy.test.js (L11, 7 assertions) covers client-side language strategy (site-wide follow / crawler skip / panel display).

6. Wiki Multilingual (docs/api/tutorial sub-sites, revised 2026-09-10)

Purpose

Wiki documentation sub-sites (docs/api/tutorial) with three-column layout + Chinese/English bilingual + fallback mechanism, sharing the same multilingual system as blog posts.

Core Conventions (required front-matter)

Directory Structure

LanguagePath
Chinese (default)source/{wiki}/ (no prefix)
Englishsource/en/{wiki}/ (/en/ prefix)

Fallback Mechanism

No English version → /en/... falls back to showing Chinese + top notice banner (“no en version”) + noindex.

Sidebar (source/_data/{wiki}-sidebar.yml)

  • Entry keys are English snake_case, display text goes through languages/*.yml translations
  • Whole-wiki encryption: configure encrypt_password at the top of the sidebar (unified encrypt_ prefix: message/placeholder/button_text optional) → all pages under that wiki are encrypted, enter the password to decrypt and render; after decryption the derived key (dk) is stored in localStorage (wiki.<wiki name>, TTL 1 day), other pages of the same wiki auto-decrypt without re-entering; encrypt_-prefixed config keys are skipped during sidebar rendering (not shown as table of contents items)

Internal Links

Absolute paths + .html (/tutorial/guide/writing.html), language prefix added automatically.

Section Numbering

Wiki pages with hand-written numbering must set closeAutoTocNum: true (same as the blog, prevents double numbering from CSS auto-numbering).

Adding a New Wiki Page

  1. Write Chinese source/{wiki}/xxx.md (front-matter layout: wiki + wiki: <sub-site>)
  2. Add English source/en/{wiki}/xxx.md
  3. Update source/_data/{wiki}-sidebar.yml
  4. Add translation keys for 9 languages (languages/*.yml)
  5. hexo clean rebuild

Wiki Tag-Component Styles & Layout Width

Wiki pages have additional layout considerations for tag components (note / ::: containers / tabs):

Style scoping: Tag component CSS is entirely scoped under .post-container descendant selectors. The wiki <main> must carry both post-container and wiki-main classes for components to receive styles. If new tag component CSS is added without a .post-container prefix, it will be invisible on wiki pages.

Layout width: Wiki <main> requires explicit width: 100% (_base/media.styl .wiki-main { width: 100% }), otherwise the flex item’s auto margin triggers shrink-to-fit, causing inconsistent widths across wiki pages (pages with less content become narrower). max-width is controlled by the global .post-container rule, keeping all wiki pages at uniform width.

Test verification: readmode-integration.test.js asserts wiki <main> contains post-container class and .wiki-layout width is consistent across wiki pages.

Automated Testing

tools/tests/release-test.sh L2b: en page 200 + fallback notice banner + comment path normalization + default language no prefix; L2y: wiki encrypted page decryption + sidebar has no encrypt_ junk titles.

Unified Refresh After Decryption (Added 2026-09-09)

After encrypted content is decrypted, components in the content need re-initialization (before decryption it’s ciphertext, DOM lacks these elements):

ComponentAction After Decryption
Code blocks (code-area)codeWidget() scans new pre elements to generate toolbar (language label/copy/collapse/fullscreen)
Image lightboxarticleInit() wraps img → .img-item + lightGallery binding (shared for post/wiki)
Mermaid diagramsevents.refresh() triggers refresh callback to re-render (data-processed idempotent)
Layout (AOS/Masonry)boot.refresh() → refreshLayout re-arranges

Unified trigger point: hbe-bundle onSuccess (all encryption scenarios: post/gallery/wiki/snippet shared). Each listener retains only its unique handling:

  • Post: tocbot reinit (post TOC)
  • Wiki: TOC encryption state removal + tocbot reinit
  • Gallery: initGallery()

Idempotent protection: codeWidget data-code-processed, mermaid data-processed, articleInit destroys old instance and rebuilds — repeated calls don’t produce duplicate elements.

Test assertion: After decryption, .code-toolbar count equals .code-area count; image wrapping .img-item + container lg-uid attribute exists.

13. PWA

Configuration (root _config.yml + userConfig/sw.tmp.js)

sw.tmp.js is the Service Worker template; CI injects offline cache version 17lai-cache-{timestamp} to generate source/sw.js.

Implementation Effect

  • Installable (manifest)
  • Offline caching of static assets
  • Auto-refresh on version update

Test assertion: /sw.js is accessible, SW registration works (localhost exempted).

SW Version Comparison & Auto-Refresh

The CI-injected cache key 17lai-cache-{timestamp} is treated as a new version whenever it changes. When registering the SW, updatefound (new SW installed) and controllerchange are monitored; the old and new cacheStorageKey are compared: if changed, the page auto-refreshes once (no prompt, the user doesn’t need to manually refresh). sw.tmp.js uses skipWaiting on install + clients.claim() on activation to take over immediately, and cleans up old 17lai-cache-* caches.

15. Design Tokens & CSS Variable Architecture

Purpose

Unify design tokens (border-radius / shadows / transitions / spacing / font sizes) through a three-layer delivery chain to CSS custom properties for site-wide reference, avoiding hardcoded values.

Configuration (theme _config.yml design section)

Three-Layer Delivery Chain

  • Scheme layer: source/css/_schemes/matery.styl (aligned with NexT _schemes/ mechanism, extensible for future schemes)
  • Font size: root font size calc(var(--font-size-base) * var(--font-scale)), preference panel adjusts --font-scale for site-wide rem proportional scaling

Implementation Effect

Components reference tokens uniformly (consistent border-radius / shadows / spacing); changing one value in the design section applies site-wide.

Test assertion: CSS contains --font-scale rule and root font size calc(... * var(--font-scale)).

⚠️ Known Pitfalls

Pitfall 1: Double Section Numbering

Symptom: Headings render as “1. 1. Overview” (two numbers).

Cause: Theme CSS auto-adds numbers to h2–h6 by default; hand-written numbers (e.g. ## 1. Overview) stack on top.

Fix: Pages with hand-written numbering add closeAutoTocNum: true in front-matter; pages without hand-written numbering must not add this field.

This article already correctly sets closeAutoTocNum: true (front-matter line 19).

Pitfall 2: Encryption ↔ TOC Conflict

Symptom: When a wiki is encrypted as a whole, the TOC is hidden by design.

Cause: In encryption mode the TOC component is skipped (intended behavior).

Fix: Test assertions must not hard-code “TOC must exist”. Encrypted wiki pages not showing TOC is normal behavior, not a bug.

Pitfall 3: Wiki English Pages Missing lang: en

Symptom: Sidebar links point to /docs/ instead of /en/docs/.

Cause: wiki_sidebar uses page.lang || default_lang; omitting lang: en falls back to the default language path.

Fix: All pages under source/en/tutorial/ must include lang: en. Verify: for f in source/en/tutorial/**/*.md; do grep -L 'lang: en' "$f"; done.

Pitfall 4: _config.tmp.yml Comment Lines Must Be Preserved

Symptom: Attempted to delete comment lines to slim the file, was vetoed and fully reverted.

Cause: User explicitly declared comment lines are useful reserves (may be restored in the future).

Fix: Never delete or modify comment lines in userConfig/_config.tmp.yml.

Pitfall 5: Config Changes Require Clean Build

Symptom: Changed configuration but the page didn’t update.

Cause: Hexo’s caching mechanism doesn’t auto-detect configuration changes.

Fix: After changing config or source/_data/*, you must run npm run clean && npm run build. Build logs showing INFO Deleted database. and INFO Deleted public folder. confirm clean ran successfully.

Pitfall 6: source/_data/* Incremental Cache Misjudgment

Symptom: After modifying source/_data/friends.yml and other data files, the page is blank or data doesn’t update.

Cause: Hexo’s incremental cache incorrectly judges “cached, unchanged” (Cache hash updated but Data model not written).

Fix:

  • Local: rm -f db.json && npm run build
  • Container: tools/cicd.sh -d (includes clean + generate + config injection)
  • In-container pm2 restart is not enough: pm2 caches old db.json content in memory
