This article is both a complete usage tutorial for matery theme interaction & visual features and an automated test arena.
Covers: code block enhancements, image lightbox, typewriter, page effects, simplified/traditional Chinese conversion, reading progress bar, back-to-top, reward popup, print styles.

How to read: for every feature, look at the Effect first (real rendering or behavior description), then the Corresponding config (the minimal snippet that produces that effect); when you need to look up parameters, jump straight to the “All tunable keys” table.

1.4 Boundaries & conflicts

  • copy_btn / show_full / shrink are three independent buttons that can be combined freely; turning all off leaves a bare code block.
  • The language label is only output when language.enable: true; unrecognized languages fall back to language.default.
  • Any change in this section requires a clean build to take effect (see Pitfalls #5).

Code Block Delegation Idempotency (codeWidget)

Encrypted wiki page code block buttons (collapse/copy) fail on click. Root cause: codeWidget() is called multiple times (page load + post-decryption refresh), accumulating click delegates on document; classList.toggle executes an even number of times, producing no net effect. Fix: named handler (_codeWidgetClickHandler) calls removeEventListener before add; Prism fallback callback gets _codeWidgetPrismRegistered idempotency flag.

Test assertion: readmode-integration.test.js “codeWidget second invocation still works with single click”.

Wiki Page Line Numbers (prism line-numbers)

Wiki documentation pages (layout/wiki.ejs) render code blocks with prism and enable line-numbers, coexisting with the article page code block enhancements (toolbar).

Test assertion: TC-L15 G5 (tools/tests/wiki-prism-integration.test.js, 4 assertions): tutorial page loads / prism-core / code blocks / line-numbers.

1.5 Summary

  • Minimal: language.enable + copy_btn is enough
  • Afraid of exploding long posts: tune height_limit; show_full provides the “expand” bar
  • Want fewer wrapped lines: break: true wraps instead of horizontal scrolling
  • Changes not taking effect: almost always cache — clean build (Pitfall 5)

2.4 Boundaries & conflicts

  • It only applies to body images (wrapped as .img-item by articleInit()); banners/covers/card thumbnails are out of scope.

Image Size Injection Preprocessing (imgsize.js)

Before the lightbox opens, the theme script scripts/events/lib/imgsize.js injects real width/height into all <img> elements on the page (prevents CLS):

  • Local images: synchronously reads file dimensions and injects directly
  • Remote images: cache hit uses cached values; CDN→local mapping (image_size_plugin.map_paths) reads local file; others fetched asynchronously
  • Persistent cache: image_sizes_cache.json (30-day TTL, 5000-entry cap)
  • Regex compatibility: matches src in three forms (double-quoted / single-quoted / unquoted), compatible with hexo-minify’s quote stripping

This script runs before lightbox binding, ensuring articleInit() wrapping img → .img-item already has dimension attributes, so the lightbox opening doesn’t trigger reflow.

Test assertion: images are wrapped as .img-item, clicking opens .lg-outer.

2.5 Summary

  • Works out of the box: image_zoom.enable: true, then write plain Markdown images
  • Body images only: covers/thumbnails never enter the lightbox
  • First-screen jumping: check whether imgsize.js runs before the lightbox rather than changing lightbox parameters

  • localStorage viewCount > 1 (prevents loading on first visit)
  • With desktop_only: false the gate is skipped (loads on mobile too)

4.5 Summary

  • Minimal: effects.enable + one line of page.default picks the effect
  • Multiple in one group is useless: only default takes effect
  • Nothing on desktop: check the width is > 1400px first, then viewCount (not loaded on first visit)
  • Changed your mind: switch from the floating panel instead of editing config repeatedly

MethodPurpose

Learning path: enter read mode → see the floating ball → exit animation → code fullscreen → expand mechanism → boundaries

17.1 How to enable

Effect: clicking the read mode button (#read_mode) in the post info bar (post-info) fills the screen with the whole post card (.card-block-fullscreen) and hides other page elements; click again to exit.   • Read mode and code fullscreen are two independent classes: entering read mode does not fullscreen code blocks, and vice versa.

⚠️ Known Pitfalls

Pitfall 1: Double Section Numbering

Symptom: Headings render as “1. 1. Overview” (two numbers).

Cause: Theme CSS auto-adds numbers to h2–h6 by default; hand-written numbers (e.g. ## 1. Overview) stack on top.

Fix: Pages with hand-written numbering add closeAutoTocNum: true in front-matter; pages without hand-written numbering must not add this field.

This article already correctly sets closeAutoTocNum: true.

Pitfall 5: Config Changes Require Clean Build

Symptom: Changed effects/subtitle.typed/image_zoom etc. configuration but the page didn’t update.

Cause: Hexo’s caching mechanism doesn’t auto-detect configuration changes.

Fix: After changing config, you must npm run clean && npm run build. Changing only article content (e.g. images/text) doesn’t require clean; incremental builds work normally.
