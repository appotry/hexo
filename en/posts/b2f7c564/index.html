学 SQL 最容易踩的坑，不是语法难，而是你照着 A 数据库的教程写，拿到 B 数据库上跑不通。SQL 有 ISO 标准，但现实中几乎没有哪个数据库完全照标准实现——它们各有方言。这篇教程以标准为主线，把方言差异逐条标出来。文中示例均在 SQLite 3.46.1 和 PostgreSQL 16.3 实测通过。

一、SQL 是什么：五类命令

SQL（Structured Query Language）是操作关系型数据库的语言。按用途分五类：

分类全称干什么代表语句
DDLData Definition Language定义结构CREATE / ALTER / DROP / TRUNCATE
DMLData Manipulation Language操作数据INSERT / UPDATE / DELETE
DQLData Query Language查询数据SELECT
DCLData Control Language权限控制GRANT / REVOKE
TCLTransaction Control Language事务控制BEGIN / COMMIT / ROLLBACK

多数教程只列前四类，把 TCL 漏了。事务是数据库区别于普通文件存储的核心能力，不该漏。

三条实用建议：

  1. 写"通用 SQL"时不要用任何私有语法。AUTO_INCREMENT、反引号、LIMIT m,n 全是方言，换个库就废。
  2. SQL 标准语法优先。比如分页用 OFFSET ... FETCH NEXT ... ROWS ONLY（PG、SQL Server 支持；MySQL 8 不支持，SQLite 不支持——所以实战里 LIMIT/OFFSET 反而更通用）。
  3. 不确定就查官方文档，别信二手教程。网上一大半教程把 MySQL 语法当"SQL 通用语法"讲。

六、NULL：最容易出错的地方

NULL 不是"0"，也不是空字符串，它是"未知"。这导致三条反直觉的规则。

6.1 比较要用 IS NULL，不能用 = NULL

任何值和 NULL 比较，结果都是"未知"，WHERE 会把它当假丢掉。

6.2 聚合函数会跳过 NULL

表里 3 行，但 age 有一行是 NULL，所以 COUNT(age) = 2。SUM/AVG/MAX/MIN 同理都会跳过 NULL。AVG 的分母是"非 NULL 的行数"，不是总行数——算平均分时极易出错。

6.3 空值替换

COALESCE 接受多个参数，返回第一个非 NULL 值，是标准写法，优先用它。

九、子查询

IN vs EXISTS：当子查询结果可能含 NULL 时，NOT IN 会返回空集（因为 x != NULL 是未知）——这是经典陷阱。用 NOT EXISTS 代替 NOT IN 更安全。

十五、索引与查询计划

复合索引的顺序有讲究：(age, name) 能加速 WHERE age=? 和 WHERE age=? AND name=?，但不能加速只有 WHERE name=? 的查询（最左前缀原则）。

看执行计划

看到 SCAN（SQLite）/ Seq Scan（PG）/ ALL（MySQL 的 type 列）就说明在全表扫描，该考虑加索引了。

十六、视图

视图是保存下来的查询，不是数据副本——每次查视图都会重新执行底层查询。它可以简化复杂查询、限制列级访问权限（只暴露部分列给某类用户）。

十七、事务

事务的原子性保证了转账这类操作要么全成、要么全不成，不会出现"钱扣了没到账"的中间态。

隔离级别

级别脏读不可重复读幻读
READ UNCOMMITTED可能可能可能
READ COMMITTED否可能可能
REPEATABLE READ否否可能
SERIALIZABLE否否否

默认值差异：MySQL InnoDB 默认 REPEATABLE READ，PostgreSQL 默认 READ COMMITTED。这个差异会导致同样的代码在两个库上表现不同，做并发相关的逻辑时务必确认。

十八、权限（DCL）

MySQL 的 'user'@'host' 是它的特色（同一用户名从不同主机连可以是不同的账号）。SQLite 没有用户概念，文件权限就是它的全部安全模型。

十九、常见错误与最佳实践

19.1 三个高频错误

① 保留字当表名/列名

user、order、group、select 都是保留字。最好的做法是加前缀（app_user、shop_order），从根上绕开。

② 字符串拼接导致 SQL 注入

永远用参数化查询（? 或 $1 占位）。这是安全底线，不是风格问题。

③ 在 WHERE 里对索引列做运算

19.2 最佳实践清单

  1. 命名有意义：student_id 而不是 sid
  2. 不用 SELECT *：写死需要的列
  3. 参数化查询：防注入
  4. 索引按需建：查询频繁的列建，写入频繁的表别乱建（索引会拖慢写入）
  5. 金额用 DECIMAL，不用 FLOAT
  6. UPDATE/DELETE 前先 SELECT 验证 WHERE
  7. 大事务拆小：长事务会长期持锁
  8. 定期备份：mysqldump / pg_dump / sqlite3 .backup
